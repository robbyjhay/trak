3. LAYERING
================================================================================

Request flow:
  middleware (public vs authed shell)
    → route handler
      → parse + zod validate
      → rate limit
      → requireSession / requireRole
      → service method
        → prisma transaction
      → map to DTO (never leak passwordHash)
      → jsonOk / jsonError

Rules:
  - No Prisma calls from React components
  - No business rules in route.ts beyond HTTP mapping
  - Services throw ServiceError(status, code, message)
  - DTOs strip secrets

================================================================================
4. CONTROLLERS (ROUTE HANDLERS) — PHASE 0
================================================================================

4.1 POST /api/auth/login
  Body: { username | email, password }
  Validate: non-empty, max lengths
  Rate limit: 5 / 15min / IP+username
  On success: create session row, set cookie, return { user, mustChangePassword }
  On failure: generic error "Username or password not recognised."

4.2 POST /api/auth/logout
  Require session; delete session row; clear cookie

4.3 GET /api/auth/session
  Return session user + mustChangePassword + preferences summary
  401 if invalid

4.4 POST /api/auth/password/set-initial
  Require session + mustChangePassword true
  Body: { password, confirm }
  Policy: min 12 chars (see AUDIT_05)
  Update passwordHash; clear mustChangePassword; optionally rotate session

4.5 POST /api/auth/password/change
  Require session
  Body: { currentPassword, newPassword, confirm }
  Verify current; update hash; revoke other sessions optional

4.6 POST /api/auth/register (invite-only)
  Body: { inviteToken, password, confirm } OR Head-only create user stays
    server action under /api/users (Phase 1)
  Phase 0: If product remains Head-provisioned only, register route may be
    absent; document as "invite accept" later.

4.7 Server Actions (allowed)
  loginAction, logoutAction, setNewPasswordAction — must call same services
  as HTTP routes (no duplicate logic)

6. VALIDATION
================================================================================

Use zod for all inputs.

authLoginSchema:
  username: z.string().trim().min(1).max(64)
  password: z.string().min(1).max(128)

passwordSetSchema:
  password: z.string().min(12).max(128)
  confirm: z.string()
  refine equal

Reject unknown keys (strict).

Sanitize: trim usernames; never store password plaintext.

7. MIDDLEWARE
================================================================================

Edge middleware.ts:
  - Public: /login, /rsvp, /api/auth/login, /api/health, static
  - Explicit allowlist ONLY (not /api/auth/* blanket)
  - /set-password requires valid session cookie
  - Authenticated users hitting /login → /dashboard
  - Missing session on protected pages → /login

Route middleware helpers:
  requireSession()
  requireRole('head')
  requireNotMustChangePassword() for app shell (redirect set-password)

CSRF (specified for production):
  - Validate Origin/Referer for mutating requests from browsers
  - SameSite=Lax cookies
  - Optional double-submit cookie CSRF_TOKEN for forms

================================================================================
8. ERROR HANDLING
================================================================================

Standard error body:
  {
    "error": {
      "code": "UNAUTHORIZED" | "FORBIDDEN" | "VALIDATION_ERROR" | "RATE_LIMITED" | "INTERNAL",
      "message": "Human readable",
      "details": [] // field errors optional
    },
    "requestId": "uuid"
  }

Map ServiceError → status codes.
Never expose stack traces in production.
Log full error with requestId server-side.

Never log starter passwords (remove createUser console plaintext)

Log destinations: stdout JSON → platform log drain

================================================================================
10. RATE LIMITING
================================================================================

Redis token bucket / sliding window:

  login:           5 attempts / 15 minutes / ip+username
  password reset:  3 / hour / email
  rsvp:            10 / hour / ip + 3 / hour / token
  api general:     120 / minute / user
  bootstrap legacy: 10 / minute / user (until removed)

On limit: 429 + Retry-After

If Redis unavailable in Phase 0 local dev: in-memory limiter with warning log.
Production REQUIRES Redis (AUDIT_08).
